# Срок

PWA для учебных дедлайнов. Next.js App Router, shadcn/ui, Supabase (только PostgreSQL и Auth), стандартный Web Push. Внешний cron вызывает Next.js endpoint; Supabase Cron и Edge Functions не используются.

## Запуск

```sh
npm install
cp .env.example .env.local
npm run dev
```

Без переменных Supabase доступен локальный режим: задания, календарь и архив, данные в localStorage. Облачные функции явно недоступны. Примеры добавляются только кнопкой «Посмотреть пример» и не являются пользовательскими заданиями.

## Supabase

1. Создайте бесплатный проект и выполните `supabase/schema.sql` в SQL Editor (один раз). Если база уже развёрнута по старой версии, примените недостающие миграции из `supabase/migrations` по порядку (`002` → `003` → `004` → `005` → `006`).
2. В `.env.local` добавьте URL и anon key проекта. Service role key используется только сервером, без префикса NEXT_PUBLIC.
3. В Authentication включите **Anonymous sign-ins**. Отдельной регистрации и формы входа в приложении нет: при первом открытии создаётся анонимная сессия, и она же определяет владельца заданий в RLS.
4. В URL Configuration задайте адрес опубликованного сайта как Site URL; добавьте localhost для разработки.

Анонимный аккаунт привязан к браузеру устройства. Личные задания живут в нём, общие — в группе: на втором устройстве достаточно вступить в ту же группу по ссылке-приглашению. Если анонимный вход выключен или Supabase не подключён, приложение работает в локальном режиме на localStorage и честно сообщает об этом.

## Web Push

Сгенерируйте пару ключей:

```sh
npx web-push generate-vapid-keys
```

Добавьте `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT=mailto:ваш-email` и случайный `CRON_SECRET` (минимум 32 случайных байта). Не коммитьте `.env.local`. Для уведомлений нужны HTTPS (или localhost), разрешение пользователя и подписка устройства. На iOS 16.4+ сначала добавьте сайт на домашний экран. Ключи VAPID не меняйте после создания подписок.

## Vercel

Импортируйте репозиторий как Next.js проект. Добавьте все переменные из `.env.example` в настройки Vercel и выполните deploy. NEXT_PUBLIC-переменные требуют пересборки после изменения. Собственный домен не обязателен.

## Внешний cron — раз в минуту

Настройте GET или POST на:

```
https://ВАШ-САЙТ.vercel.app/api/reminders
```

Заголовок:

```
Authorization: Bearer ВАШ_CRON_SECRET
```

Секрет передаётся только заголовком, не в URL. Ответ содержит `sent` и `failed`. Обработчик забирает до 20 напоминаний атомарно через PostgreSQL `FOR UPDATE SKIP LOCKED`. Зависшая обработка возвращается в очередь через 5 минут. Задания в архиве не отправляются; изменение срока или интервала напоминания сбрасывает отметку отправки. Интервалы напоминаний: в момент дедлайна, за 10 минут, час, 3 часа, день, 3 дня или неделю — до пяти штук на задание. Повторяющиеся задания рассылаются по своему расписанию, пока не наступил срок. Пропущенные напоминания догоняются до суток после дедлайна. При частичном сбое доставка может повториться (at-least-once); одинаковый notification tag объединяет уведомления одного задания на устройстве. Доставка Web Push и cron не гарантируют точность будильника.

Даты хранятся в UTC, форма и календарь используют часовой пояс устройства. Текст push отображает срок в Europe/Moscow и явно помечен МСК.

Supabase Free может приостановить малoактивный проект. Внешние проверки создают реальные запросы, но не заменяют гарантию доступности. Следите за предупреждениями Supabase и статусом cron.

## Push-уведомления

В форме один блок «Push-уведомление»: сверху — как часто, ниже — когда.

- **Один раз** + чипы «за 3 дня», «за день», «за час» — можно выбрать сразу несколько, придёт по одному push на каждый; если не выбрать ни одного, уведомлений не будет. Подпись под блоком всегда показывает итог словами: «Придёт за 3 дня, за день и за час».
- **Каждый день**, **По будням**, **Каждую неделю** + время «20:00» — push приходит по этому расписанию, пока не наступил срок. У «каждую неделю» день берётся из даты срока.

Время повтора считается по Москве — так же, как подпись в тексте push. Срок при этом никуда не двигается: наступил — задание уходит в архив, и уведомления по нему прекращаются.

Расписание считает `reminder_slots()`: для разового задания она возвращает по моменту на каждое выбранное напоминание, для повтора — ближайший прошедший момент по правилу. Факт доставки пишется в `reminder_deliveries` с ключом `(task_id, user_id, slot)`, поэтому у повтора каждый день свой слот и своё уведомление, а повторной отправки одного и того же слота не происходит. Строки старше недели чистятся при каждом вызове cron.

## Предметы

Предмет вводится текстом, но под полем показываются уже заведённые в группе — в один тап, частые выше. При сохранении введённое подтягивается к известному написанию без учёта регистра, поэтому «матан» не превращается во второй предмет рядом с «Матан». В списке заданий предметы становятся фильтром, а кнопка справа переключает группировку между сроками и предметами.

## Группы

Приложение рассчитано на одну группу: переключатель групп в меню появляется, только если групп больше одной. Создание и вступление в несколько групп в коде остаётся. Название группы задаёт тот, кто её создаёт (например, `J3124`), остальные вступают по ссылке-приглашению.

## Что не удаляется

После срока задание уходит в архив — не удаляется и не переносится. В архиве же лежит всё, что убрали руками: личное помечается `completed`, общее скрывается только на текущем устройстве. Просроченное возвращается в список новым сроком (в архиве у него кнопка-карандаш), убранное — кнопкой «Вернуть». Безвозвратно удалить можно лишь своё задание и только через подтверждение в диалоге; RLS не даёт удалить или изменить чужое.

## Проверка после публикации

Откройте сайт — аккаунт создастся сам. Включите уведомления и отправьте тестовый push в настройках. Создайте задание со сроком через несколько минут и напоминанием «В момент дедлайна», закройте сайт и дождитесь cron. Проверьте из второго браузера, что чужие личные задания не видны, а общие — видны всем в группе (RLS). Эти интеграционные проверки требуют настроенного Supabase и реального устройства.

Правила доступа проверяются локально на PGlite без Supabase:

```sh
node scripts/test-groups.mjs
```
